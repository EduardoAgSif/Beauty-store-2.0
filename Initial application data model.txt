  1. ENTITIES OVERVIEW
================================================================================

The application data model consists of three core entities:

  ┌──────────┐         ┌──────────────┐         ┌──────────────┐
  │  User    │         │   Product    │         │  CartItem    │
  │ (MySQL)  │         │   (MySQL)    │         │ (Client-side)│
  └──────────┘         └──────────────┘         └──────────────┘

  - User:     Represents registered customers who authenticate into the app.
  - Product:  Represents the beauty products available in the catalog.
  - CartItem: Represents a product added to the shopping cart with a quantity
              (managed in-memory on the frontend, no database persistence).

================================================================================
  2. ENTITY: User
================================================================================

  Source:  backend/schema.sql → table `users`
  Purpose: Stores registered user accounts for authentication.

  ┌─────────────┬────────────────┬──────────────────────────────────────────┐
  │ Field       │ Type           │ Description                              │
  ├─────────────┼────────────────┼──────────────────────────────────────────┤
  │ id          │ INT (PK, AI)   │ Unique identifier, auto-increment        │
  │ name        │ VARCHAR(100)   │ Full name of the user                    │
  │ email       │ VARCHAR(150)   │ Email address (unique, used for login)   │
  │ password    │ VARCHAR(255)   │ Hashed password (bcrypt)                 │
  │ created_at  │ TIMESTAMP      │ Account creation date (auto-generated)   │
  └─────────────┴────────────────┴──────────────────────────────────────────┘

  Constraints:
    - PRIMARY KEY on `id`
    - UNIQUE on `email`
    - NOT NULL on `name`, `email`, `password`

================================================================================
  3. ENTITY: Product
================================================================================

  Source:  backend/schema.sql → table `products`
           src/app/models/product.model.ts → TypeScript interface
  Purpose: Represents a luxury beauty product in the catalog.

  Database Table (MySQL):
  ┌─────────────┬────────────────┬──────────────────────────────────────────┐
  │ Field       │ Type           │ Description                              │
  ├─────────────┼────────────────┼──────────────────────────────────────────┤
  │ id          │ INT (PK, AI)   │ Unique identifier, auto-increment        │
  │ name        │ VARCHAR(150)   │ Product name                             │
  │ description │ TEXT           │ Detailed product description             │
  │ price       │ DECIMAL(10,2)  │ Price in MXN                             │
  │ stock       │ INT            │ Available inventory (default: 0)         │
  │ category    │ VARCHAR(50)    │ Product category (default: 'Skincare')   │
  │ image_url   │ TEXT           │ URL to the product image                 │
  │ created_at  │ TIMESTAMP      │ Creation date (auto-generated)           │
  └─────────────┴────────────────┴──────────────────────────────────────────┘

  TypeScript Interface (Frontend):
  ┌─────────────────┬──────────┬──────────────────────────────────────────┐
  │ Property        │ Type     │ Description                              │
  ├─────────────────┼──────────┼──────────────────────────────────────────┤
  │ id              │ number   │ Unique identifier                        │
  │ name            │ string   │ Product name                             │
  │ description     │ string   │ Product description                      │
  │ price           │ number   │ Product price                            │
  │ stock           │ number   │ Available stock                          │
  │ category?       │ string   │ Product category (optional)              │
  │ image_url?      │ string   │ Product image URL (optional)             │
  │ rating?         │ number   │ Average rating (optional, future use)    │
  │ reviews_count?  │ number   │ Number of reviews (optional, future use) │
  │ is_featured?    │ boolean  │ Featured flag (optional, future use)     │
  └─────────────────┴──────────┴──────────────────────────────────────────┘

  Categories used in seed data:
    - Skincare
    - Maquillaje
    - Fragancias
    - Cuidado Capilar

  Constraints:
    - PRIMARY KEY on `id`
    - NOT NULL on `name`, `price`

  4. ENTITY: CartItem
================================================================================

  Source:  src/app/models/cart-item.model.ts → TypeScript interface
  Purpose: Represents a product added to the user's shopping cart.
  Storage: In-memory only (client-side, no database persistence).

  ┌─────────────┬──────────┬──────────────────────────────────────────────┐
  │ Property    │ Type     │ Description                                  │
  ├─────────────┼──────────┼──────────────────────────────────────────────┤
  │ product     │ Product  │ Reference to the associated Product object   │
  │ quantity    │ number   │ Number of units of this product in the cart  │
  └─────────────┴──────────┴──────────────────────────────────────────────┘

================================================================================
  5. ENTITY RELATIONSHIPS
================================================================================

  User ─── (authenticates) ──→ App
    • A user registers and logs in to access the application.
    • No direct foreign key relationship to Product or CartItem in the DB.

  Product ←── (referenced by) ── CartItem
    • Each CartItem contains a reference to one Product.
    • A Product can appear in zero or many CartItems.
    • Relationship type: Many-to-One (CartItem → Product).

  Relationship Diagram:

    ┌──────────┐                ┌──────────────┐
    │  User    │                │   Product    │
    │──────────│                │──────────────│
    │ id (PK)  │                │ id (PK)      │
    │ name     │                │ name         │
    │ email    │                │ description  │
    │ password │                │ price        │
    │ created  │                │ stock        │
    │          │                │ category     │
    │          │                │ image_url    │
    │          │                │ created_at   │
    └──────────┘                └──────┬───────┘
                                      │ 1
                                      │
                                      │ *
                                ┌─────┴────────┐
                                │  CartItem    │
                                │──────────────│
                                │ product (FK) │
                                │ quantity     │
                                └──────────────┘

    Legend: 1 = one side | * = many side | PK = Primary Key | FK = Foreign Key

================================================================================
  7. NOTES
================================================================================

  • The CartItem entity is managed entirely on the client side (Angular service)
    and is not persisted in the database. Cart data is lost when the app is
    closed or the user logs out.

  • The TypeScript Product interface includes optional fields (rating,
    reviews_count, is_featured) that are reserved for future implementation
    and do not currently exist in the MySQL schema.

  • User passwords are hashed using bcrypt (PHP password_hash) before storage.

  • The database engine is InnoDB with utf8mb4 character set for full Unicode
    support (including emojis and special characters in product descriptions).
